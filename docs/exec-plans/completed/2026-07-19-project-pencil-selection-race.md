# 修复项目快捷新建时的选择竞态

## 目标

点击左侧项目的铅笔按钮后，新聊天输入框必须稳定切换到该项目，不能被旧项目的异步初始化结果覆盖。

## 计划

- [x] 为工作目录初始化增加版本校验，显式选择项目时使旧初始化失效。
- [x] 增加竞态回归测试。
- [x] 运行定向测试、完整测试和构建验证。
- [x] 使用真实 Chromium 验证项目铅笔切换，并检查稳定后的 DOM 状态。
- [x] 将本计划归档到 `docs/exec-plans/completed/`。

## 成功标准

- 点击项目铅笔按钮后，输入框项目显示被点击的项目。
- 较早开始的项目目录校验即使较晚完成，也不能覆盖用户的新选择。
- 普通首次进入新聊天时，已保存项目仍能正常初始化。

## Smoke Ledger

- 自动化验证：项目铅笔触发的 `project-directory-changed` 会递增选择版本，旧初始化结果无法再落地。
- 反例验证：未发生显式选择时版本保持不变，保存项目仍沿用原初始化路径。
- `npm run test`：83 个测试文件、387 个用例通过。
- `npm run test:smoke`：通过，确认使用隔离 `CODEX_HOME`。
- `npm run build`：通过；存在仓库既有的 NFT 动态路径警告。
- 真实浏览器验证：先将输入框项目设置为 `web`，再点击 `Chat` 项目的铅笔按钮；等待 3 秒后，显示标签、`data-current-project` 与 `localStorage` 均稳定切换为 `/volume2/SSD/codex/Chat`。
- 控制台检查：项目切换没有运行时异常；现有错误均为缺失的旧 `/api/settings/app`、`/api/setup`、`/api/git/status` 路由返回 404，与本次改动无关。
