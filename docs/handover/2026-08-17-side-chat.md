# 侧边聊天技术交接

配套计划：[2026-08-17-side-chat.md](../exec-plans/completed/2026-08-17-side-chat.md)

## 结论

工作区侧栏已提供与官方 Codex app 对齐的临时侧边聊天。侧聊继承主线程历史供模型参考，但 Web 消息区从空态开始；输入框直接复用 `ChatView` / `MessageInput`，没有第二套 composer。

## 协议接线

- 创建：`thread/fork`，参数包含 `ephemeral: true`、现有 developer instructions 与官方侧聊约束。
- 边界：fork 成功后调用 `thread/inject_items`，注入模型可见、UI 不展示的父子会话边界。
- 发送：子线程调用 `turn/start`，状态来自 `activeTurnsByThreadId[childThreadId]`。
- 审批：按子线程 ID 从 app-server server request 队列中选择。
- 设置：模型、推理等级和权限更新都指向子线程。
- 关闭：运行中先调用 `turn/interrupt`，随后调用 `thread/unsubscribe`；不调用 `thread/delete`。
- 已停止的临时线程不支持 `thread/read { includeTurns: true }`。Provider 精确识别该 app-server 错误，将其视为无持久历史并清理陈旧 Turn 状态，随后继续取消订阅；普通线程仍执行历史补读，其它读取错误仍向 UI 传播。

## UI 与状态

- `side-chat` 是非持久化动态标签，刷新或关闭应用后不会恢复。
- Provider 持有侧聊创建状态，收起工作区面板不会丢失运行中的侧聊。
- 官方空态说明位于消息区中央，完整输入框固定在底部。
- 关闭标签显示官方确认弹窗，并支持“不再询问”。
- 紧凑视口的工作区 Sheet 使用非模态交互，确保 Portal 中的加号菜单可点击。

## 剩余边界

- 没有已启动的 app-server 主线程时，fork 会失败并显示真实错误和重试入口。
- runtime broker 若把最大并发 Turn 限制为 1，主聊与侧聊同时运行时 app-server 会拒绝第二个 Turn；UI 保留该真实错误，不伪造并发状态。
